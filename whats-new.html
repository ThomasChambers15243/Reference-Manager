Reference Manager Download 0.7.12

What's new

Version 0.7.12 is the current one · 8 October 2026.

0.7.12

Features

  • Works packages: a project in one file, published by a lab, a research group or a person. It holds references in groups, their categories and tags, notes and, if its maker chooses, the PDFs with their highlights. A new Works packages page, between Templates and Settings, imports them, exports any project as one, and shows how to write one by hand or with an AI.
  • An imported package becomes a project of its own, after saying what it holds and what it leaves out. Its references stay out of your library until you bring them in, each checked in the reference form first, and they then take the package's categories and tags. A reference your library already has is used as it is; one it has by its title can be swapped for yours. Their keys in the project never change.
  • A package's PDFs go into Papers, linked to their references. Its highlights and notes are added only to PDFs that are new to you, so they never mix with yours. Removing a package takes back what is still only its own.
  • Drop a works package (.zip or .json) on the window to import it.
  • The library format changes (to 9). Updating from an earlier version saves a copy of your library in backups\ first.

Bug fixes

  • None in this version.

0.7.11

Features

  • Updates on a Mac, like on Windows: a few seconds after it starts, the app says when a new version is out, and Update and restart installs it. The new version takes the old one's place in Applications and opens. Copies older than 0.7.11 are updated by hand once.
  • New versions come from the website, on Windows and on a Mac: the app asks it when it starts (Settings → Updates can turn that off), downloads the new version and checks it against the size and checksum the website gives before installing it. Versions built on the same computer are still found in their folder.
  • Settings has a contents list on the left. Click a section to go to it; the one you're reading is marked as you scroll. The list scrolls by itself when the window is short, and hides when it is narrow.
  • arXiv is a kind of venue: Eprint archive, which a reference's eprint type (archivePrefix in BibTeX) draws on. A preprint shows arXiv as its venue in the library, venue:arxiv finds it, and arXiv has a page like any journal. Eprint types already typed in become venues of that kind.
  • References have categories and tags of their own, in a sidebar beside the library table, with Not organised yet.
  • References, papers, people and venues are organised the same way. Drag one, or every one ticked, onto a category or tag. Drag a category onto another to put it inside, onto the line above one to move it there, or out to the top level. Drag a tag up or down the list to reorder it. Add to category and Tag work on the ticked ones everywhere, and Remove from category or Remove the tag takes them out of the one shown. These actions float in a bar at the foot of the list, so ticking the first one no longer moves the list.
  • The library format changes (to 8). Updating from an earlier version saves a copy of your library in backups\ first.

Bug fixes

  • Install from a file… takes installers named as the website names them (Reference-Manager_0.7.11_x64-setup.exe) and, on a Mac, a .dmg.

0.7.10

Features

  • None in this version.

Bug fixes

  • Search: a quoted phrase with a colon in it ("BERT: Pre-training…") is searched for, instead of being read as a filter and finding nothing.
  • Search: a range that ends before it starts (year:2023..2019, date:2019-03) now says so, instead of quietly finding nothing.
  • Formatted references: no full stop or comma after a title ending in ? or ! ("need? Journal", not "need?. Journal"), and "Why? A study" instead of "Why?: A study".
  • Formatted references, CSL-JSON and RIS: a DOI typed as a link (https://doi.org/10.…) is no longer printed twice.
  • Formatted references: names print as typed ("d'Alembert", not "d' Alembert"; "van Gogh, V.", not "Gogh, V. van").
  • A name copied from a PDF with its accent stored apart no longer creates a second copy of the same person. .bib files get the accents joined up, which pdfLaTeX needs.
  • People list: each reference counts once, however many projects changed its author list.
  • Notes saved as Markdown: a line of = under a comment no longer makes it a heading, an indented line no longer turns into code, the title is escaped, and a picture whose note ends in \ still shows.
  • A project's timeline export: a note on a paper since linked to a reference outside the project stays with the project's reference.
  • Colour groups: Duplicate works for names close to the 60-character limit.
  • Pasting a very long BibTeX text is much faster.

0.7.9

Features

  • None in this version.

Bug fixes

  • A reference form left open in a background tab no longer freezes the whole window. Links inside the form (a person, a venue, a note, a citing paper) open their tab behind it, and the tab shortcuts wait while a form or dialog is open.
  • On a Mac the tab shortcuts are ⌘T, ⌘W and ⌘1–9 only, because Ctrl+T swaps two letters in a text box there.
  • Keys: a key typed with Set key… while linked files were being written is no longer overwritten.
  • Keys: copying or saving one group's file from Export & sync records (and with locked keys pins) only the keys in that file, and only when the copy worked.
  • Keys: "Use the new keys" no longer marks a project that was never written out as written.
  • Templates: a Templates page opened before an abbreviation tag or a kind of venue was deleted no longer saves it back.
  • Templates: the sidebar's Templates link no longer throws away unsaved edits.
  • .bib files:
    • A month stored on its own uses the template's month style (jun, June).
    • In BibLaTeX, the subtitle is protected like the title.
    • Field order and omit lists naming year or school also work for BibLaTeX's date and institution.
    • The [key] token writes Müller as Muller, not Mller.
  • No "its typed key is used" warning for a reference whose key is pinned.
  • A project's formatted references follow the order you arranged them in.
  • Export & sync opens on the project's own file, so the warnings button shows that file's warnings.
  • Check document's "Select them in the project" shows every reference, so every tick counts.
  • Add to project counts only the references that weren't in the project already.

0.7.8

Features

  • None in this version.

Bug fixes

  • Closing a tab or window keeps what you were typing: notes on people and venues, a paper's details, notes on a page, text on a board.
  • Ctrl+Enter in the reference form adds a name you're still typing instead of dropping it, and no longer picks a suggestion as well.
  • Reference form:
    • Asks before Reset, Push to master, or opening a PDF or project would drop your other changes.
    • A new reference's form starts empty.
    • A second pasted BibTeX text shows its own form.
    • Saving to one project only no longer turns an old date into the project's own.
  • Dates: a year before Christ (-0044) is left as typed; years below 1000 keep four digits (0800-03).
  • Paper viewer:
    • A reference opened after starting "Type its reference" no longer gets linked to the paper.
    • Page notes and the Notes panel no longer undo each other's changes, and quick changes in Details no longer undo each other.
    • Find works on pages you've scrolled away from.
    • A reopened paper shows the right page number.
    • Numbered citations lead to the right reference.
    • Pinch zoom follows your fingers instead of jumping.
  • Papers dragged onto a category are put in it.
  • The citation graph keeps its view when you come back to its tab.
  • Projects: the selection count and Remove ignore references hidden by a group or filter.
  • People and venues:
    • A merge starts afresh for each pair, and Cancel keeps the selection.
    • A right click no longer opens a link.
    • Typing in one abbreviation survives adding another.
  • Settings keeps the key pattern you're editing when another setting is saved.
  • Templates:
    • Built-in templates can no longer be reordered by dragging.
    • Duplicate asks about unsaved changes.
    • Emptying a text chip no longer deletes it.
  • Boards: a group only goes into a larger one (no more refused saves), and a board reopens where you left it.
  • Notes: an undo during a save no longer leaves the note unsaved, and a project's notes keep their own open folders.
  • Timeline: the shading stays with the days, months and years as you move along.

0.7.7

Features

  • None in this version.

Bug fixes

  • Security: a web page in a browser tab could load the app in a frame and, on Windows, use the app's commands. Both are now refused.
  • Security: a javascript: link in formatted references no longer runs. Links there and in the timeline export open as web links instead of taking over the window.
  • Web pages can no longer press the app's keys.
  • Windows:
    • A tab dragged to another window no longer opens in every window.
    • Windows fit small or scaled screens and open on the screen you dropped a tab on.
  • On a Mac, Quit (⌘Q) saves what you were typing, as closing a window does, and Option+←/→ moves by a word again.
  • The copies made before an update are kept by date, so the newest is no longer deleted.
  • Browser tabs:
    • Get the PDF stops waiting after half a minute.
    • A PDF downloaded for a deleted reference still arrives.
    • Add this PDF works again after a failed download.
    • A tab remembers its reference.
  • Footnotes in notes lead to their note instead of an error.

0.7.6

Features

  • None in this version.

Bug fixes

  • A backup saved over the library's own file could delete the library. That's refused now.
  • A restore that partly worked was reported as failed, and could lose the copy of the previous library.
  • Writing linked files:
    • No longer overwrites an edit made outside the app at the same moment.
    • Keeps the file's permissions on a Mac.
    • No longer replaces a shortcut (symlink) with a plain file.
  • Watched folders:
    • PDFs in a folder that couldn't be read are no longer forgotten.
    • Half-downloaded files wait until they're complete.
    • A failed import is tried again.
  • Adding a PDF again brings back its stored file if it went missing.
  • Search in papers: letters like ı, ø, ł, ß and æ now match, and results are no longer cut off for big libraries.
  • Relinking a paper to another reference updates its citation matches.
  • Notes:
    • Citations written as @{key} are linked.
    • Saving notes as files gives a usable name to one Windows reserves (like Aux).
  • A new project no longer inherits a deleted project's timeline. A deleted abbreviation tag or kind of venue is taken out of templates.
  • Merging people or venues no longer leaves project copies identical to the library's.

0.7.5

Features

  • None in this version.

Bug fixes

  • .bib files:
    • A part of a book with its own title is an @incollection in BibTeX, instead of losing the book's title.
    • Initials like J.A. stay J.A. (not J.).
    • A month kept beside a year-only date is no longer dropped.
    • An impossible date (30 February) keeps its year and month.

  • Renaming keys in .tex files stops if an \input can't be read, instead of skipping that file.

0.7.1

Features

  • Papers are named by the title printed in them instead of their file name.
  • The library as a .zip: save everything (database, PDFs, pictures) and restore it, from Settings → Your data.
  • cola keys write the initials of up to four more authors, then +N.

Bug fixes

  • Citation cards find the reference lists of many more papers.
  • Hover cards show reliably, and clicking a citation goes to its reference.
  • Going back no longer leaves a blue box over the page.
  • Cancel on a reference and Stop in a pasted-BibTeX review ask before throwing changes away.
  • Ctrl+Shift+W closes the window, not the tab, and Light or Dark reaches every open window.

Known issues

  • LaTeX maths in a title ($\alpha$-Synuclein) shows without the symbol in the library table and in formatted references.
  • If the same board is edited in two windows at the same moment, the last save wins for an item changed in both.
